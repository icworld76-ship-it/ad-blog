생성형 AI와 깃허브 자동화 저장소를 활용해 아마존 KDP용 32페이지 컬러링북이나 인쇄용 도서 원고를 완성했다면 이제 마지막 관문이 남습니다.

바로 KDP에 실제 파일을 제출하기 전 인쇄 규격을 점검하는 과정입니다.

AI로 멋진 그림을 만들고 32페이지 원고까지 완성했더라도 이미지 크기, 재단 여백, 안전 영역, 표지 규격 등이 맞지 않으면 수정 작업이 필요할 수 있습니다.

특히 처음 KDP 출판에 도전하는 경우 화면에서 보기에는 아무 문제가 없는 PDF가 실제 인쇄 규격에서는 문제가 되는 경우가 있습니다.

이전 포스팅에서 KDP 전자책 자동화 저장소 관리법을 다뤘다면 이번 글에서는 한 단계 더 나아가 실제 출판 파일을 제출하기 전에 무엇을 확인해야 하는지 정리해보겠습니다.

핵심은 세 가지입니다.

이미지 품질을 충분히 확보하고, 재단 영역을 정확하게 설정하고, 최종 PDF와 표지를 업로드 전에 다시 검증하는 것입니다.


1. 아마존 KDP 출판 전 반드시 확인해야 할 4가지

KDP용 인쇄 파일을 만들 때 가장 먼저 확인해야 할 것은 이미지 품질입니다.

컴퓨터나 스마트폰 화면에서는 선명하게 보이는 이미지라도 실제 책 크기로 인쇄하면 화질이 떨어질 수 있습니다.

두 번째는 재단 여백입니다.

페이지 끝까지 그림이나 배경이 이어지는 책이라면 인쇄 후 종이를 자르는 과정까지 고려해 Bleed 영역을 설정해야 합니다.

세 번째는 안전 영역입니다.

제목이나 페이지 번호, 중요한 글자, 캐릭터의 얼굴처럼 잘려서는 안 되는 요소를 페이지 가장자리 가까이에 배치하면 실제 제작 과정에서 문제가 발생할 수 있습니다.

네 번째는 표지 규격입니다.

표지는 앞표지만 만드는 것이 아니라 책의 형태에 따라 뒷표지와 책등까지 포함한 전체 크기를 계산해야 합니다.

페이지 수, 용지 종류, 책 크기에 따라 표지 크기가 달라질 수 있기 때문에 최종 제출 단계에서는 KDP에서 제공하는 표지 계산 기준을 확인하는 것이 안전합니다.


2. 300DPI 이미지 해상도는 어떻게 확인할까?

KDP용 인쇄 이미지를 준비할 때 흔히 등장하는 숫자가 300DPI입니다.

여기서 중요한 것은 이미지 파일의 DPI 정보만 300으로 바꾸는 것이 아닙니다.

실제 인쇄 품질을 결정하는 핵심은 이미지가 최종 인쇄 크기에 필요한 충분한 픽셀을 가지고 있는가입니다.

예를 들어 8인치 너비로 이미지를 인쇄하면서 300PPI 수준의 품질을 확보하려면 단순 계산으로 가로 약 2,400픽셀이 필요합니다.

8 × 300 = 2,400픽셀

따라서 작은 이미지를 그대로 두고 파일 정보의 DPI 숫자만 300으로 변경한다고 실제 이미지 품질이 좋아지는 것은 아닙니다.

AI 이미지 생성 도구를 사용할 때도 마찬가지입니다.

생성된 이미지의 실제 픽셀 크기를 먼저 확인하고 책의 최종 인쇄 크기에 비해 부족하다면 적절한 업스케일링 작업을 진행하는 것이 좋습니다.

컬러링북처럼 선이 중요한 콘텐츠라면 더욱 세심하게 확인해야 합니다.

가는 선이나 작은 디테일은 화면에서는 깨끗해 보여도 인쇄 과정에서 흐릿하게 표현될 수 있기 때문입니다.

따라서 최종 PDF를 만들기 전에 모든 페이지 이미지의 픽셀 크기를 동일한 기준으로 검사하는 것이 좋습니다.


3. 재단 여백과 안전 영역은 무엇이 다를까?

KDP를 처음 시작할 때 가장 혼동하기 쉬운 개념 가운데 하나가 Bleed와 안전 영역입니다.

Bleed는 인쇄 후 종이를 재단하면서 잘려나갈 가능성이 있는 영역까지 이미지나 배경을 확장해 두는 개념입니다.

페이지 가장자리까지 배경이나 그림이 이어지는 디자인이라면 재단 과정에서 흰 선이 생기지 않도록 Bleed를 고려해야 합니다.

반대로 안전 영역은 반드시 보존되어야 하는 중요한 요소를 페이지 가장자리에서 떨어뜨려 배치하는 개념입니다.

예를 들어 다음과 같은 요소가 해당됩니다.

책 제목

페이지 번호

설명 문구

캐릭터 얼굴

중요한 그림 요소

이런 요소는 재단선 가까이에 배치하지 않는 것이 좋습니다.

또 하나 중요한 것이 안쪽 제본 여백입니다.

책의 가운데 부분은 제본 방식과 페이지 수에 따라 실제로 펼쳤을 때 일부 영역이 안쪽으로 들어가 보일 수 있습니다.

따라서 중요한 글자나 그림을 책의 안쪽 끝부분에 너무 가깝게 배치해서는 안 됩니다.

정확한 여백값은 책의 판형, 페이지 수, Bleed 사용 여부 등에 따라 달라질 수 있으므로 최종 제작 단계에서는 해당 도서 조건에 맞는 KDP 규격을 기준으로 확인해야 합니다.


4. 32페이지 PDF를 만들기 전 최종 체크

32페이지 컬러링북을 제작한다고 가정해보겠습니다.

이미지 생성이 모두 끝났다고 바로 PDF로 합치는 것보다 먼저 전체 페이지를 검사하는 것이 좋습니다.

첫 번째는 페이지 수입니다.

page-01부터 page-32까지 파일이 정확하게 존재하는지 확인합니다.

중간에 page-17이 빠지거나 같은 페이지가 두 번 들어가는 실수는 의외로 쉽게 발생합니다.

두 번째는 이미지 크기입니다.

32장의 이미지가 모두 같은 캔버스 크기와 비율을 사용하는지 확인합니다.

세 번째는 이미지 품질입니다.

최종 인쇄 크기를 기준으로 충분한 픽셀을 확보했는지 확인합니다.

네 번째는 재단 설정입니다.

Bleed를 사용하는 책인지 사용하지 않는 책인지 먼저 결정하고 이에 맞게 전체 내지 파일을 제작해야 합니다.

다섯 번째는 폰트입니다.

PDF에 텍스트를 직접 사용했다면 해당 폰트가 정상적으로 포함되어 있는지 확인하는 것이 좋습니다.

여섯 번째는 투명 효과입니다.

일부 디자인 프로그램이나 이미지 생성 과정에서 투명 레이어나 효과가 남아 있을 수 있습니다.

최종 PDF 변환 과정에서 예상하지 못한 결과가 발생하지 않도록 실제 출력 파일을 다시 확인해야 합니다.


5. 표지는 내지와 별도로 검증해야 한다

KDP 초보자가 놓치기 쉬운 부분이 표지입니다.

내지 PDF가 완벽하더라도 표지 크기가 맞지 않으면 다시 수정해야 할 수 있습니다.

종이책 표지는 일반적으로 앞표지와 뒷표지, 그리고 조건에 따라 책등 영역까지 하나의 전체 파일로 제작합니다.

여기서 중요한 것은 책등 폭이 고정되어 있지 않다는 점입니다.

책의 페이지 수와 용지 종류 등에 따라 필요한 표지 규격이 달라질 수 있습니다.

따라서 예전에 만든 다른 책의 표지 크기를 그대로 복사해서 사용하는 것은 피하는 것이 좋습니다.

새로운 책을 만들 때마다 해당 책의 판형과 페이지 수를 기준으로 표지 규격을 다시 확인하는 것이 안전합니다.

특히 32페이지처럼 페이지 수가 적은 책은 책등에 텍스트를 넣을 수 있는 조건도 별도로 확인해야 합니다.


6. 깃허브로 KDP 수정 이력을 관리하는 이유

KDP 파일을 제출한 뒤 수정이 필요하다는 사실을 알게 됐다고 가정해보겠습니다.

일반 폴더에서 작업한다면 기존 PDF를 열고 바로 수정한 뒤 같은 이름으로 저장하기 쉽습니다.

문제는 이렇게 하면 이전 버전이 사라진다는 것입니다.

깃허브를 사용하면 상황이 달라집니다.

먼저 제출했던 파일 상태를 기록으로 남깁니다.

그다음 문제가 발견된 페이지나 표지를 수정합니다.

그리고 어떤 부분을 변경했는지 커밋 메시지에 기록합니다.

예를 들면 다음과 같습니다.

Fix page 12 image resolution

Adjust cover bleed

Move title inside safe area

Replace page 24 artwork

이렇게 관리하면 나중에 어떤 문제가 있었고 어떻게 수정했는지를 다시 확인할 수 있습니다.

여러 권의 책을 제작할수록 이 기록은 매우 유용한 출판 데이터가 됩니다.


7. 자동 검증 시스템까지 연결해보자

지난 글에서 만든 깃허브 저장소 구조를 활용하면 일부 검증 작업을 자동화할 수도 있습니다.

예를 들어 새로운 이미지가 저장소에 추가될 때 다음 항목을 자동으로 확인하도록 만들 수 있습니다.

이미지가 정확히 32장인지

파일명이 page-01부터 page-32까지 이어지는지

이미지 픽셀 크기가 기준보다 작은 것은 없는지

모든 이미지의 가로세로 크기가 동일한지

최종 PDF 페이지 수가 정확한지

필수 표지 파일이 존재하는지

이런 기본적인 검사를 자동화하면 사람이 반복적으로 확인해야 하는 작업을 상당히 줄일 수 있습니다.

다만 자동 검증만 믿고 바로 KDP에 제출해서는 안 됩니다.

최종 단계에서는 사람이 직접 PDF 전체를 넘겨보면서 이미지 위치, 잘림, 페이지 순서, 표지 상태를 확인하는 것이 좋습니다.


8. KDP 제출 직전 최종 체크리스트

마지막으로 실제 업로드 직전에 다음 사항을 다시 확인합니다.

- 32페이지가 정확한 순서로 구성되어 있는가
- 각 이미지가 최종 인쇄 크기에 필요한 충분한 픽셀을 가지고 있는가
- Bleed 사용 여부와 실제 파일 설정이 일치하는가
- 중요한 글자와 그림이 안전한 위치에 배치되어 있는가
- 안쪽 제본 영역에 중요한 요소가 지나치게 가까이 있지 않은가
- PDF의 폰트와 이미지가 정상적으로 표시되는가
- 투명 효과나 예상하지 못한 레이어 문제가 없는가
- 표지 크기가 현재 책의 판형과 페이지 수에 맞는가
- 앞표지와 뒷표지의 중요한 요소가 재단 영역과 충돌하지 않는가
- KDP 미리보기에서 전체 페이지를 다시 확인했는가


결론

아마존 KDP 출판에서 가장 아까운 실수는 책을 거의 완성한 뒤 규격 문제 때문에 다시 처음부터 파일을 수정하는 것입니다.

이를 방지하는 가장 좋은 방법은 제작 단계부터 검증 과정을 하나의 작업 순서로 만드는 것입니다.

AI 이미지 생성 단계에서는 충분한 픽셀을 확보합니다.

내지 제작 단계에서는 Bleed와 안전 영역을 고려합니다.

PDF 생성 단계에서는 페이지 수와 이미지 크기를 검사합니다.

표지 제작 단계에서는 현재 책의 판형과 페이지 수에 맞는 규격을 다시 확인합니다.

그리고 최종 제출 전에는 KDP 미리보기를 이용해 전체 결과를 직접 확인합니다.

여기에 깃허브 버전 관리까지 연결하면 문제가 발생하더라도 이전 상태와 수정 내역을 쉽게 추적할 수 있습니다.

결국 중요한 것은 한 번의 출판을 성공시키는 것이 아니라 다음 책에서도 그대로 반복할 수 있는 검증 시스템을 만드는 것입니다.

32페이지 컬러링북 한 권에서 시작한 작업이 여러 권의 KDP 프로젝트로 늘어날수록 이러한 자동화와 검증 체계의 가치는 더욱 커집니다.
