블로그를 시작하려고 하면 대부분 티스토리나 워드프레스부터 떠올린다.

물론 훌륭한 플랫폼이다. 하지만 조금만 시야를 넓혀 보면 전 세계 개발자와 콘텐츠 제작자들이 오래전부터 사용해 온 또 다른 선택지가 있다.



처음 이름만 들으면 개발자만 사용하는 서비스처럼 느껴진다. 나 역시 그랬다.

하지만 직접 사용해 보니 생각이 완전히 달라졌다.

GitHub Pages는 개발자만을 위한 서비스가 아니라, 자신의 콘텐츠를 오래 남기고 싶은 사람에게도 상당히 매력적인 플랫폼이었다.

## 가장 큰 장점은 역시 무료다

GitHub Pages의 가장 큰 장점은 비용 부담이 거의 없다는 점이다.

호스팅 비용을 따로 내지 않아도 되고, GitHub 저장소만 있으면 누구나 웹사이트를 운영할 수 있다.

도메인을 연결하면 일반 홈페이지처럼 사용할 수도 있다.

블로그를 처음 시작하는 사람이라면 비용 부담 없이 경험을 쌓기에 좋은 환경이다.

## 속도가 빠르다

GitHub Pages는 정적 사이트다.

방문자가 글을 읽을 때마다 데이터베이스를 불러오는 방식이 아니라 이미 만들어진 페이지를 그대로 보여 준다.

덕분에 로딩 속도가 빠르고 서버 부담도 적다.

검색엔진 역시 빠르게 열리는 사이트를 긍정적으로 평가하는 경우가 많기 때문에 속도는 생각보다 중요한 요소다.

## 관리가 생각보다 쉽다

처음에는 GitHub라는 이름 때문에 어렵게 느껴질 수 있다.

하지만 한 번 구조를 이해하면 의외로 단순하다.

글을 작성하고 저장소에 올리면 자동으로 사이트가 갱신된다.

최근에는 GitHub Actions를 활용해 배포 과정도 대부분 자동화할 수 있다.

처음 세팅이 조금 어려울 뿐, 이후에는 글 쓰는 데 집중하면 된다.

## 콘텐츠는 결국 내 자산이다

SNS는 언제든 알고리즘이 바뀔 수 있다.

플랫폼 정책이 달라질 수도 있다.

하지만 GitHub Pages는 내가 관리하는 저장소를 기반으로 운영된다.

콘텐츠를 직접 보관하고 원하는 형태로 관리할 수 있다는 점은 장기적으로 큰 장점이다.

블로그를 오래 운영할 생각이라면 이런 차이는 시간이 지날수록 더욱 크게 느껴진다.

## SEO에도 불리하지 않다

GitHub Pages는 정적 사이트이기 때문에 검색엔진이 페이지를 읽기 쉽다.

물론 좋은 글을 쓰는 것이 가장 중요하지만, 사이트 구조 역시 검색 노출에 영향을 준다.

제목, 설명, 이미지, 메타데이터 등을 꾸준히 관리한다면 충분히 검색 유입을 기대할 수 있다.

실제로 해외에서도 GitHub Pages를 이용해 기술 블로그나 개인 브랜딩 사이트를 운영하는 사례를 쉽게 찾아볼 수 있다.

## 직접 운영해 보니 느낀 점

처음에는 파일명 하나 바꾸는 것도 낯설었다.

이미지가 보이지 않아 한참을 헤매기도 했고, 날짜 형식 하나 때문에 글이 목록에 나타나지 않기도 했다.

하지만 그런 과정을 하나씩 해결하다 보니 플랫폼을 이해하게 됐다.

오히려 그 경험 덕분에 블로그가 어떻게 만들어지고 배포되는지까지 자연스럽게 익힐 수 있었다.

## 마치며

GitHub Pages는 화려한 플랫폼은 아니다.

하지만 무료이고, 빠르며, 안정적이고, 콘텐츠를 내 자산으로 관리할 수 있다는 장점이 있다.

블로그를 오래 운영하고 싶은 사람이라면 한 번쯤은 반드시 경험해 볼 만한 플랫폼이다.

처음에는 조금 낯설다.

하지만 한 번 익숙해지면 "왜 진작 시작하지 않았을까?"라는 생각이 들 수도 있다.
